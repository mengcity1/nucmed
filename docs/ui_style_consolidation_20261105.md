### 2.1 三条事故链（都在今天）

1. **研发阶段的 `bg-brand` 无效** → `.app-stage.light :is(button…)` 用

## 三、目标结构（4 层，单一职责）

```
L1 tokens      颜色 / 半径 / 阴影 / 动效 —— 只在这里出现字面量（CSS 变量 + tailwind.config）
L2 primitives  .surface（玻璃面板）  .control（按钮/chip 基座）  .is-selected（唯一选中语义）
L3 components  .tab / .chip / .card 只**组合** primitive，不再重复画玻璃
L4 pages       页面层不出现 bg-white / 色号；选中一律用 .is-selected
```

**关键约定（治本）**：
- `.is-selected` 的**可见性由 primitive 保证**（实底 **或** `::after`/徽标，二选一必居其一），
  页面只负责加这个 class，不再各自决定"用什么颜色表示选中"。
- 玻璃装饰**只允许一处实现**（`.control`），主题差异通过 `.app-stage.dark` 覆盖**同一处**。
- 新增 `!important` 需要在该行注释里写明"对抗哪条 vendor 规则"（vendor 的 `.lg-stage button`
  确实需要它，其余大多不需要）。

## 六、把"事故"变成门（`scripts/check_ui_tokens.py`，建议随 S2 一起做）

1. **选中态必居其一**：源码里每个 `.*-on` / `is-selected` 的类，样式必须包含
   实底（`background-color` 不透明）**或** `::after`/徽标标记 —— 只调 `background-image`
   的淡色渐变 ⇒ 判红（今天的两次事故都能挡住）。
2. **`!important` 棘轮**：计数不得增加（现值 **115**，目标单向下降到 < 25）。
3. **规则块棘轮**：`.chip*` / `.tab*` / `:is(button` 的块数不得增加（现 31 / 18 / 17）。
4. **色值白名单**：`index.css` 新增的 `#rrggbb` 必须已在 tokens 或白名单里（防再散落）。
